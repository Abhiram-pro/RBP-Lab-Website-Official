Build the UI for two pages: /publications and /news. UI AND PLACEHOLDER DATA ONLY — real
content gets wired in later.

For each page, create a separate data file exporting a typed array with 4–6 obviously-fake
placeholder entries. The page component imports and renders that array and contains no
inline content. Keep field names exactly as specified — a later step replaces these files
wholesale.

Placeholder text must be obviously fake ("Placeholder publication title one", "Author A,
Author B", "Journal Name"). Do not write realistic-looking scientific titles, author names,
journals, or DOIs.

  year: string;        // "2026"
  doi?: string;        // bare form, e.g. "doi.org/10.1016/j.example.2025.123456"
  extra?: string;      // ISBN, volume, page range
  type: PublicationType;
}

                                                and at least 3 different years */ ];

### Page UI

PAGE HEADER — eyebrow "RNA-Binding Proteins (RBPs) Laboratory", h1 "Publications", lede
"Research output spanning RNA biology, splicing regulation, and computational genomics."

CONTROLS, inside the page header band, in a row:
  - A search input with a magnifier icon inside it. Filters live across citation, venue,
    and year. Needs a real <label> (visually hidden is fine) and type="search".
  - A "Filter" dropdown with a checkbox per type (Journal Publications, Conference
    Publications, Books, Book Chapters), all checked by default. When some are unchecked,
    show a small count badge on the trigger. Selecting an item must NOT close the menu.
  - A visually-hidden live region (role="status") announcing the result count.

RESULTS — grouped first by type, then by year within each type.
  - Type heading at h2 scale with the count in parentheses, above a top hairline rule.
  - Within a type, entries group by year, NEWEST FIRST. Two-column layout: a narrow left
    column holding the year in monospace, and the entries on the right. On desktop the year
    is position:sticky so it stays visible while its group scrolls past. Stacks on mobile.
  - Each entry is two lines: the citation, then a smaller muted line reading
    "venue · year" plus the DOI and extra when present. Hairline rule between entries.
  - Render the doi field as a link to https://<doi> — target="_blank",
    rel="noopener noreferrer". Only when the field exists; never construct one.

EMPTY STATES
  - Search matches nothing: `No publications match "<query>".`
  - All types unchecked: "No publication type selected."

Build this so it handles ~63 entries gracefully — that's the real volume.

LIST — an ordered list, newest first, numbered DESCENDING (the newest item carries the

  - the number in monospace in a narrow left column
  - mono uppercase category line

## APPLIES TO BOTH
═══════════════════════════════════════════════

- Use <Section>, <SectionHeader>, <PageHeader> and the tokens from the scaffold. No
  hardcoded colours anywhere.
- Both pages must render correctly with an EMPTY array and with 60+ entries. Don't assume
  a fixed count.
- Filtering and grouping logic goes in the page component or a small hook — not inside the
  data file. The data file is pure data.
- Do not add pagination, infinite scroll, sort dropdowns, "share" buttons, citation-export
  buttons, or per-item detail routes. None of those are in scope.
