Build the UI for three pages: /equipment, /collaborators and /gallery. UI AND PLACEHOLDER
DATA ONLY — real content gets wired in later.

Same convention as before: one typed data file per page, placeholder entries only, page
components import and render. Keep field names exactly as specified.

For placeholder images use a neutral grey block or a solid-colour data-URI at the right
aspect ratio. Do NOT pull stock photography from Unsplash or any other source — these
slots will hold real photographs of real people and real lab equipment, and stock images
have previously ended up shipped to production here.

  model: string;         // manufacturer, model and price, as one line
  description: string;
  funding: string;       // funding body and grant number
  imageSrc: string;
  accent: string;        // per-item accent colour, hex — this one IS data, not theme
}

export const EQUIPMENT: EquipmentItem[] = [ /* 6 placeholders */ ];

### Page UI

PAGE HEADER — eyebrow "Equipment", h1 "Lab Instrumentation", lede "Core equipment
supporting our RNA biology, proteomics, and cell biology research programs. Each entry
lists the grant it was procured under."

GRID — 1 column mobile, 2 tablet, 3 desktop. Each card is a flex column so the funding
line bottom-aligns across a row regardless of description length:
  - 4:3 image, object-cover, rounded, hairline border
  - a short 2.5rem accent rule beneath the image, coloured from the item's accent field
  - name at h3 scale
  - model line in the accent colour, medium weight
  - description paragraph
  - funding line in small mono uppercase, above a top hairline rule, prefixed "Funded by "

The accent field is intentionally per-item data rather than a theme token — these are
category markers. It is the only place a component may read a colour from data.

### Page UI

PAGE HEADER — eyebrow "RNA-Binding Proteins (RBPs) Laboratory", h1 "Collaborators", lede
"Research partnerships spanning genetics, computer science, and engineering — within
IIT Guwahati and beyond."

GRID — same responsive shape as equipment. These people have no photographs, so build a
<Monogram> component instead: a generated avatar showing the person's initials, derived
from the name at render time, on a tinted background using the item's accent colour, in a
4:3 or square frame. Do not use photo placeholders, and never substitute a stock portrait.

Each card: monogram, then name at h3 scale, institution in muted text, then the
description line.

  alt: string;
}

export const GALLERY_IMAGES: GalleryImage[] = [ /* 8 placeholders with MIXED aspect

### Page UI

PAGE HEADER — eyebrow "RNA-Binding Proteins Laboratory · IIT Guwahati", h1 "Gallery", lede
"Photographs from the lab, the department, and the people who work here."

GRID — 1 column mobile, 2 from tablet up. Each image keeps its OWN aspect ratio from the
width/height fields — do not force a uniform ratio and do not crop. Reserve the correct
box before load so nothing shifts when images arrive (use the width/height, or an
aspect-ratio wrapper).

Lazy-load everything below the fold; the first two load eagerly. Fade each image in on
load. Alt text comes from the data, never generated.

No lightbox, no captions, no filter/category tabs.

## APPLIES TO ALL THREE
═══════════════════════════════════════════════

- Use <Section>, <PageHeader> and the scaffold tokens. The per-item `accent` fields are the
  ONLY colours that may come from outside the token system.
- Every page renders correctly with an empty array and with 3× the placeholder count.
- No "request access", "book equipment", "contact collaborator", or enquiry forms.
- No invented specifications, prices, grant numbers, or institution names in the
  placeholders — keep them transparently fake.
